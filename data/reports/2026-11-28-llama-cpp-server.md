## 复测与验收

- 取官方 macOS arm64 归档 `b12774`，验证 SHA-256 `70311c4751ed3221e63f47769327dd088d7400f76dcfb81c66ec843db165814d`。程序报告构建 12774、提交 `171527522`。复用并核对之前下载的 Qwen2.5-0.5B-Instruct Q4_K_M GGUF。CPU 推理、1024 上下文、1 个 slot、独立回环端口。未测试其他平台、GPU、容器或多模型路由。
- 实际观察到健康检查 503 后变 200。模型列表包含 `local-qwen`。普通和流式聊天都返回 `LOCAL_OK`，流式以 `[DONE]` 结束。流式非文本块可以有 null 内容。重复 `/v1` 返回 404。单模型模式下，请求随意的模型标识仍得到 200 和实际模型 ID。
- 第二次启动用独立临时 key 文件，健康接口无鉴权仍返回 200，模型列表无令牌返回 401，正确令牌返回 200。服务器退出后两个测试端口均关闭。保留不含凭据的 JSON 观察记录。
- 复用现有本机 API 探测脚本，新增 `llama-cpp` 标签。用实际服务器验证脚本读取模型、普通响应和完整流式响应。现有脚本的两种运行时标签和回环限制继续可用。
